## Файл конфігурації сервера

### Мова інтерфейсу

```
language: en
```

- **language** — мова інтерфейсу. Підтримувані значення: `"uk"` (українська, за замовчуванням) та `"en"` (англійська).
  Цей параметр впливає на весь текст, що бачить користувач: форму реєстрації, кнопки, прогрес, повідомлення про помилки та відображення результатів.
  Панель адміністратора (огляд, тести, файли, налаштування, доступ, статистика) і повідомлення сервера в ній використовують ту саму мову.
  Зміни застосовуються одразу при збереженні через панель адміністратора без перезапуску сервера; відкрита сторінка адмінки змінить мову після оновлення.

### Додатковий CSV з відповідями та інформацією про користувача

```
extra_answers_with_users_csv: true
```

- **extra_answers_with_users_csv** — якщо встановлено `true`, сервер
  додатково генерує **третій** CSV-файл поруч зі стандартними файлами
  відповідей та користувачів. Префікс `extra_` підкреслює, що файл
  створюється на додачу до двох стандартних; частина `answers_with_users`
  описує, що саме об'єднано. Файл має ім'я
  `<тест>_<NNNN>.answers_with_users.csv` і містить по одному рядку на кожну
  надіслану відповідь. На початку кожного рядка додаються стовпці `user_id`,
  `username` та всі поля з `registration.fields`, що дозволяє одразу
  аналізувати дані без потреби об'єднувати два існуючі CSV-файли вручну.
  За замовчуванням `false`. Зміни застосовуються без перезапуску сервера —
  набудуть чинності при наступному переключенні або перезапуску тесту.

### Навігація по питаннях

```
question_navigation: true
```

- **question_navigation** — показує на сторінці тесту кнопки з номерами питань у тестах,
  де пропуск питань вимкнено (`allow_skip_questions` не увімкнено). Ними користувач може
  повернутися до вже відкритих питань. У тестах із пропуском питань кнопки є завжди.
  За замовчуванням `false`: кнопок немає, питання йдуть одне за одним.
  Застосовується без перезапуску. В адмінці, розділ **Налаштування** (вигляд «Форма»): **Навігація по питаннях, коли пропуск вимкнено**.

### Розділ `server`

```
server:
  host: "0.0.0.0"
  port: 8080
  include_ipv6: false
  url_format: "http://{IP}:{PORT}/"
```

- **host** — визначає, на яких мережевих інтерфейсах сервер приймає з'єднання.
  - `"127.0.0.1"` — сервер буде доступний лише з цього ж комп'ютера (локально).
  - `"0.0.0.0"` — сервер буде доступний усім пристроям у локальній мережі (через Wi-Fi або Ethernet).
  Використовуйте `"0.0.0.0"`, якщо до тестування підключаються інші пристрої у вашій локальній мережі.
- **port** — порт, на якому працює сервер.
  За замовчуванням використовується `8080`. Якщо цей порт зайнятий, можна змінити його, наприклад, на `8000`.
  Також його можна вказати в командному рядку: `webquiz --port 8000` — це значення має вищий пріоритет за файл конфігурації.
- **include_ipv6** — чи включати IPv6 адреси до списку мережевих інтерфейсів.
  За замовчуванням `false`. Якщо встановлено `true`, IPv6 адреси відображатимуться у списку URL-адрес для доступу з інших пристроїв.
- **url_format** — формат URL-адреси для відображення в адмін-панелі.
  За замовчуванням `"http://{IP}:{PORT}/"`. Використовуйте плейсхолдери `{IP}` та `{PORT}`.
  Приклад для зворотного проксі: `"http://{IP}/webquiz/"`

### Розділ `paths`

```
paths:
  quizzes_dir: "quizzes"
  archive_dir: "archive"
  static_dir: "static"
```

Розділ `paths` задає розташування службових папок. Якщо зазначені каталоги відсутні, вони створюються автоматично при першому запуску.

- **quizzes_dir: "quizzes"**
  Папка для збереження тестів у форматі YAML.
  При першому запуску в ній створюється приклад тесту `default.yaml`.
  Усередині також може бути підпапка **`imgs`**, де зберігаються зображення, що використовуються у питаннях.

- **archive_dir: "archive"**
  Архів проходжень тестів. Кожне переключення або перезапуск тесту створює в ньому теку `РРРР-ММ-ДД-ГГХХСС-<тест>` з усіма даними цього проходження:
  - `answers.csv` — відповіді користувачів з датою і часом кожної відповіді;
  - `users.csv` — дані користувачів із реєстраційними полями, оцінкою та загальним часом проходження тесту (ГГ:ХХ:СС);
  - `answers_with_users.csv` — лише коли `extra_answers_with_users_csv: true`: рядки відповідей з доданими спереду `user_id`, `username` та реєстраційними полями;
  - `server.log` — журнал роботи сервера за час цього проходження;
  - `summary.json` — числа для таблиці розділу **Архів** (службовий файл).
  CSV-файли можна відкрити у будь-якому табличному редакторі (Excel, Google Sheets). Параметри `logs_dir` і `csv_dir` попередніх версій більше не використовуються: якщо вони є у файлі, сервер їх ігнорує (з попередженням у лозі).

- **static_dir: "static"**
  Папка зі статичними веб-файлами.
  Основний файл **index.html** є службовим і генерується або оновлюється автоматично.
  Редагувати його вручну не потрібно.

### Розділ `admin`

```
admin:
  master_key: a1
```

- **master_key** — ключ доступу до адміністративного інтерфейсу.
  Якщо ключ **вказано**, адміністратор може відкрити панель управління з будь-якого пристрою у мережі, ввівши цей ключ.
  Якщо ключ **не вказано**, адміністративна панель буде доступна **лише з локальних адрес** (наприклад, `127.0.0.1` або `localhost`), і у цьому випадку введення ключа **не потрібно**.

### Розділ `registration` (необов'язковий)

```
registration:
  approve: false
  username_label: "Ім'я користувача"
  fields:
    - Grade
    - School
  disabled_fields:
    - Teacher
    - City
  field_options:
    Grade:
      - "9"
      - "10"
      - "11"
```

Розділ визначає, як користувачі реєструються перед проходженням тестів.

- **approve**
  Якщо встановлено `true`, користувач після заповнення форми не зможе почати тест одразу — його заявка потрапить у список очікування, і адміністратор має схвалити її вручну. Поки заявку не схвалено, користувач може виправити ім'я та інші поля: клік на ім'я вгорі сторінки (з іконкою ✎) відкриває діалог (кнопка **Зберегти зміни**); адміністратор одразу бачить нові дані. Після схвалення дані змінити вже не можна, а відкритий діалог закривається сам.
  Якщо значення `false`, користувач може почати тестування одразу після реєстрації.
  У файлі `webquiz.yaml`, який сервер створює під час першого запуску, стоїть `approve: true`; без цього рядка у файлі діє `false`.

- **username_label**
  Налаштовує текст підпису для поля введення імені користувача у формі реєстрації.
  За замовчуванням: відповідає налаштуванню `language` — `"Ім'я користувача"` для `uk`, `"Username"` для `en`.
  Приклади використання:
  ```
  username_label: "Прізвище та ім'я"
  username_label: "Логін учня"
  username_label: "Student Name"
  ```
  Цей підпис відображається як у формі реєстрації, так і у діалозі редагування даних під час очікування схвалення.
  Підтримує спеціальні символи, емодзі та багатомовний текст.

- **fields**
  Додаткові поля реєстрації, які з'являються у формі перед початком тесту.
  Наприклад:
  ```
  fields:
    - Клас
    - Школа
    - Місто
  ```
  Усі зібрані дані автоматично потрапляють у CSV-файл результатів.

- **disabled_fields**
  Додаткові поля реєстрації, які залишаються в конфігу, але не показуються у формі реєстрації. Використовуйте цей список, щоб «приховати» поля, які ви часто вмикаєте та вимикаєте, не втрачаючи їхні назви.

  У розділі адмінки **Налаштування** (вигляд Form) поряд із кожним додатковим полем є чекбокс: зніміть позначку, щоб перемістити поле зі списку `fields` до `disabled_fields`, поставте її назад, щоб поле знову показалось у формі реєстрації. Збереження форми просто переміщує поле між двома списками — нічого не видаляється, тож ви можете в один клік увімкнути поле пізніше.

- **field_options**
  Визначені значення для додаткових полів: назва поля → список значень. Таке поле — це випадний список (з пошуком) замість поля для введення тексту, у тому ж порядку, у якому задано значення; сервер приймає лише значення зі списку (і під час редагування даних в очікуванні схвалення). В огляді адмінки колонка такого поля сортується в порядку значень, а не за абеткою. Поля без значень приймають довільний текст.
  У формі **Налаштування** адмінки значення — це список під кожним полем (згорнутий, розгортається кнопкою **Значення для вибору**): їх можна додавати, редагувати, видаляти й переставляти вище/нижче.

### Розділ `appearance` (необов'язковий)

```
appearance:
  background_color: "#1f2937"
  background_image: "/imgs/background.jpg"
```

Фон сторінки тесту для користувачів.

- **background_color** — колір у форматі hex (`#rgb` або `#rrggbb`). За замовчуванням темний `#1f2937`.
- **background_image** — картинка на всю сторінку замість кольору: файл із `quizzes/imgs/` (записується як `/imgs/назва.jpg`) або повна адреса `https://`. Порожнє значення (за замовчуванням) — лише колір. Поки картинка завантажується, видно колір під нею.

В адмінці, у розділі **Налаштування** (вигляд «Форма»), блок **Фон сторінки тесту** перемикає **Колір** (вибір кольору з рекомендованими варіантами) і **Зображення** (вибрати файл із `quizzes/imgs/` кнопкою **Вибрати** або вписати шлях чи адресу) і показує попередній перегляд. Застосовується без перезапуску: сторінка тесту отримує новий фон одразу після збереження.

### Розділ `quizzes` (необов'язковий)

```
quizzes:
  - name: "Basic Math Quiz"
    download_path: "https://example.com/quizzes/math.zip"
    folder: "math_questions/"
```

Цей розділ дозволяє адміністратору завантажувати тести із зовнішніх джерел через адміністративний інтерфейс.

- **name** — назва тесту, яка відображається в адмін-панелі.
- **download_path** — посилання на архів із тестом (наприклад, `.zip`).
- **folder** — папка, у яку буде розпаковано вміст архіву після завантаження.

### Розділ `tunnel` (необов'язковий)

**Варіант 1: Отримання конфігурації з сервера**
```
tunnel:
  server: "tunnel.example.com"
  public_key: "keys/id_ed25519.pub"
  private_key: "keys/id_ed25519"
  socket_name: "my-quiz-socket"  # Необов'язково: фіксоване ім'я сокета (за замовчуванням: випадкові 6-8 символів)
  # Конфігурація буде завантажена з https://tunnel.example.com/tunnel_config.yaml
```

**Варіант 2: Локальна конфігурація (без завантаження з сервера)**
```
tunnel:
  server: "tunnel.example.com"
  public_key: "keys/id_ed25519.pub"
  private_key: "keys/id_ed25519"
  config:  # Необов'язково: вкажіть локально, щоб пропустити завантаження з сервера
    username: "tunneluser"
    socket_directory: "/var/run/tunnels"
    base_url: "https://tunnel.example.com/tests"
```

Розділ `tunnel` дозволяє налаштувати SSH-тунель для публічного доступу до локального сервера через зовнішній тунельний сервер. Це корисно для:
- Запуску тестів з локального комп'ютера без налаштування проброса портів
- Тимчасового публічного доступу без виділеного хостингу
- Класних кімнат, де учні підключаються поза локальною мережею

**Параметри:**

- **server** — доменне ім'я або IP-адреса тунельного сервера (наприклад, `"tunnel.example.com"`).
  Це сервер, який забезпечує публічний доступ до вашого локального WebQuiz.

- **public_key** — шлях до файлу публічного SSH-ключа.
  Якщо файл не існує, WebQuiz автоматично згенерує пару ключів ED25519.
  Приклад: `"keys/id_ed25519.pub"`

- **private_key** — шлях до файлу приватного SSH-ключа.
  Використовується для автентифікації на тунельному сервері.
  Приклад: `"keys/id_ed25519"`

- **socket_name** (необов'язково) — фіксоване ім'я сокета замість випадкової генерації.
  Дозволяє мати передбачувану URL-адресу для публічного доступу через тунель.
  Якщо не вказано, генерується випадковий ідентифікатор довжиною 6-8 символів.
  Потрібне для надсилання файлів між серверами: це ім'я, за яким інші сервери знаходять цей.
  Використовуйте літери, цифри, `-`, `_` та `.`.
  Після відключення те саме ім'я може бути зайняте до 5 хвилин, поки тунельний сервер не видалить старий файл сокета.
  Приклад: `"my-quiz-socket"`

- **config** (необов'язковий підрозділ) — локальна конфігурація тунелю.
  Якщо вказано, WebQuiz використає цю конфігурацію замість завантаження з сервера.
  - **username** — SSH користувач для підключення до тунельного сервера
  - **socket_directory** — каталог на сервері для Unix domain sockets
  - **base_url** — базовий URL для доступу до тунелю (наприклад, `"https://tunnel.example.com/tests"`)

**Як це працює:**

1. **Автоматична генерація ключів**: Якщо ключі відсутні, WebQuiz автоматично створює пару ключів ED25519 без парольної фрази.

2. **Управління з адмін-панелі**: Відкрийте адміністративну панель, щоб переглянути статус тунелю.

3. **Копіювання публічного ключа**: Скопіюйте згенерований публічний ключ і додайте його до файлу `~/.ssh/authorized_keys` на тунельному сервері.

4. **Підключення**: Натисніть кнопку "Підключити" в адмін-панелі для встановлення тунелю.

5. **Публічний URL**: Після підключення відобразиться публічний URL (наприклад, `https://tunnel.example.com/tests/a3f7b2/`).

6. **Автоматичне перепідключення**: Якщо з'єднання обривається, WebQuiz автоматично намагається відновити його.

**Вимоги до сервера:**
- Тунельний сервер повинен підтримувати переадресацію через Unix domain sockets
- Сервер має надавати endpoint `tunnel_config.yaml` за адресою `https://[server]/tunnel_config.yaml` з наступними параметрами:
  ```yaml
  username: tunneluser
  socket_directory: /var/run/tunnels
  base_url: https://tunnel.example.com/tests
  ```

**Примітки щодо безпеки:**
- SSH-ключі генеруються без парольної фрази для автоматичного підключення
- Приватний ключ зберігається з правами доступу 600 (тільки для власника)
- Підключення ініціює адміністратор (немає автоматичного підключення при запуску)
- Статус з'єднання відображається в реальному часі через WebSocket
